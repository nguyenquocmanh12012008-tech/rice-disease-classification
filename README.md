# Rice Leaf Disease Classification with DenseNet

A PyTorch image-classification project based on a custom DenseNet-style model for rice leaf disease images from the [Paddy Doctor Kaggle competition](https://www.kaggle.com/competitions/paddy-disease-classification).

> **Implementation and test status:** The original notebook had incomplete or misspelled model definitions; the modules below repair those defects while preserving its model layout and training settings. On 2026-10-10, the runnable notebook completed one training epoch on Kaggle with the competition dataset and CUDA. It reported 56.37% validation accuracy and generated a checkpoint and submission file in the Kaggle session. The modular `src` command-line scripts have not been run independently, and the Kaggle outputs and dataset are not included in this repository.

## Project Overview

This project classifies rice leaf images by disease category using a custom DenseNet-style network in PyTorch. Its longer-term motivation is to support earlier disease awareness for farmers, especially in Central Vietnam.

The intended use is decision support. This repository does not establish that the model is accurate on field images or that it can replace an agricultural expert.

## Problem Statement

Rice leaf symptoms can be difficult to distinguish by visual inspection. The project explores whether a deep learning classifier can map a leaf image to one of the categories in the Paddy Doctor dataset. The competition provides labeled training images and a separate unlabeled test set.

## Dataset

The author selected [Paddy Doctor: Paddy Disease Classification](https://www.kaggle.com/competitions/paddy-disease-classification). Kaggle documents 10,407 labeled training images across ten categories and 3,469 competition test images. Its train.csv includes image_id, label, variety, and age; labeled images are organized under class-named folders. See the [competition data page](https://www.kaggle.com/competitions/paddy-disease-classification/data) and [official rules](https://www.kaggle.com/competitions/paddy-disease-classification/rules) for access and usage terms.

The refactored loader expects the training images under train_images/. It uses torchvision.datasets.ImageFolder, whose class-to-index mapping follows the folder names. The mapping is saved to results/class_to_idx.json after training. The 3,469 competition test images are not used for local evaluation because their labels are not provided.

The training notebook splits the labeled images randomly into training and validation subsets: int(0.2 * N) validation images and the remainder for training, using a torch.Generator seeded with 123. This split is not stratified. No dataset is included in the repository; see [data/README.md](data/README.md).

## DenseNet Architecture

The notebook defines a custom DenseNetB121 model; it does not use torchvision's pretrained DenseNet. Its dense blocks concatenate each layer's newly generated feature maps with the feature maps already present. Each bottleneck uses a 1x1 convolution to expand to 4 × growth_rate channels, then a 3x3 convolution to produce growth_rate new channels. Transition layers apply BatchNorm and ReLU, halve the channel count with a 1x1 convolution, and halve the feature-map dimensions with average pooling.

| Component | Configuration read from the notebook |
| --- | --- |
| Input | RGB image resized to 224 × 224 |
| Stem | BatchNorm → ReLU → 7x7 convolution (64 channels, stride 2) → 3x3 max pooling (stride 2) |
| Dense blocks | 6, 12, 24, and 16 bottleneck layers |
| Growth rate | 32 channels |
| Transitions | After the first three blocks; channel count and spatial dimensions are each halved |
| Head | Adaptive global average pooling → fully connected layer → raw logits |
| Classes | 10, matching the competition training folders |

The initial BatchNorm/ReLU-before-convolution order is retained as written in the notebook. The model code fixes the notebook's missing DenseBlock forward method, class-name mismatches, misspelled third transition references, and lowercase nn.linear typo. The notebook had no usable checkpoint, so compatibility with an existing trained weight file could not be checked.

## Installation and Setup

From the repository root, create a virtual environment and install the listed packages:

~~~bash
python -m venv .venv
python -m pip install -r requirements.txt
~~~

Use Python 3.10 or newer. Place the competition files in the layout described in [data/README.md](data/README.md). The default loader path is data/raw/paddy-disease-classification/; pass either the competition root or its train_images/ directory. A CUDA GPU is used when available; otherwise, the script selects CPU. Compatible PyTorch/Torchvision versions still need to be selected for the target environment.

## Training

The default settings copied from the notebook are one epoch, batch size 32, four data-loader workers, Adam with eps=0.05 and the PyTorch default learning rate, and cross-entropy loss. Images are resized to 224 × 224 and converted to tensors in the [0, 1] range. No additional normalization or augmentation is applied.

Run from the repository root:

~~~bash
python -m src.train --data-root data/raw/paddy-disease-classification
~~~

On Kaggle, pass the competition path you provided:

~~~bash
python -m src.train --data-root /kaggle/input/competitions/paddy-disease-classification
~~~

The code saves the final model state dictionary, epoch history, and class mapping under results/. The modular command-line entry point has not been run independently; the notebook test results are recorded below.

## Evaluation Metrics and Results

The training pipeline records cross-entropy loss and accuracy for the training and validation subsets after each epoch. src.evaluate evaluates the same seeded validation split and reports validation loss and accuracy.

The Kaggle run of `notebooks/rice_densenet_training.ipynb` used CUDA and completed one epoch on the 10,407 labeled images. The seeded random split contained 8,326 training images and 2,081 validation images. The custom model had 6,912,818 parameters.

| Metric | Training | Validation |
| --- | ---: | ---: |
| Loss | 1.6619 | 1.3716 |
| Accuracy | 42.37% | 56.37% |

The epoch took 81.5 seconds. These are one-epoch holdout metrics, not a Kaggle leaderboard score. The notebook also ran inference over the competition test images and created `submission.csv`; the file was not submitted to the competition. The checkpoint, history, class mapping, and submission remain in the Kaggle session at `/kaggle/working/results/`. They are not included in this repository, and the modular `src.train` and `src.evaluate` commands have not been independently tested.

After training, evaluate the saved model with:

~~~bash
python -m src.evaluate \
  --data-root data/raw/paddy-disease-classification \
  --checkpoint results/densenetb121_paddy.pth
~~~

## Limitations

- The validation split is random and not stratified.
- No data augmentation or image normalization beyond ToTensor() is used.
- The competition dataset and generated checkpoint/results are not included in this repository; they remain in the Kaggle session.
- Performance on field images, including images from Central Vietnam, has not been evaluated.
- Similar disease symptoms, lighting, background, camera angle, and image quality may affect predictions.
- Predictions should support awareness and follow-up, not replace assessment by an agricultural expert.
